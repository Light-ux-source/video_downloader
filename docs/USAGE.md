# 使用手册

## 1. 界面结构

界面是**不对称三栏**布局（刻意避开"导航栏 + 卡片网格"的通用模板脸）：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 · 引擎版本 · ffmpeg 状态 · 并发数 · 时钟 · 扫描线开关 · 说明  │
├────────────┬─────────────────────────────────────────────────────────┤
│            │  ▸ COMMAND DECK   命令行风格的输入框 + 画质 + 高级参数    │
│ TELEMETRY  ├─────────────────────────────────────────────────────────┤
│ 系统遥测    │  SIGNAL INSPECT   解析结果：封面/元信息/全部画质          │
│ · 引擎      ├─────────────────────────────────────────────────────────┤
│ · ffmpeg    │  DOWNLOAD QUEUE   任务队列：进度/遥测/日志/操作           │
│ · 并发      │                                                         │
│ · 磁盘      │                                                         │
│ · 统计      │                                                         │
└────────────┴─────────────────────────────────────────────────────────┘
```

### 顶栏

| 元素 | 说明 |
|---|---|
| 引擎徽标 | 绿色 = yt-dlp 可用；红色 = 不可用（需跑 `./setup.sh`） |
| ffmpeg 徽标 | 绿色 = 就绪；黄色 = 缺失（高清合流与 MP3 转码将不可用） |
| 并发 | 当前进行中 / 最大并发 |
| 时钟 | 本机时间 |
| 扫描线按钮 | 切换 CRTS 扫描线视觉效果（个人偏好，不影响功能） |
| 使用说明 | 展开三步上手与 Cookies 提示 |

### 左侧遥测栏

- **ENGINE / FFMPEG / DOWNLOAD / QUEUE**：依赖状态与队列概况
- **完成率、磁盘剩余**：进度条
- **完成 / 失败 / 取消**：累计计数
- 底部提示：服务仅监听本机回环地址

### 主工作台（Command Deck）

- **单个链接 / 批量投递** 两种模式切换
- URL 输入框是命令行风格（`▸` 提示符）。解析时底部有扫描线锁相动画
- 右侧：剪贴板粘贴按钮、解析/投递按钮
- **画质** 一行：最佳画质 / 1080P / 720P / 480P / 360P / 仅音频
- **附加** 一行：内嵌字幕 / 整个播放列表 / 跳过已存在
- **高级参数** 可折叠面板（见第 3 节）

### 解析结果（Signal Inspect）

- 空态：等待信号提示
- 视频：封面（带扫描线）、标题、UP 主、站点/时长/播放量/发布日/字幕/直播、
  下载按钮、打开原页、**查看全部画质**（可点选精确 format id）
- 播放列表：条目列表（可点标题跳原页）+ 「下载整个列表」按钮

### 任务队列（Download Queue）

每条任务卡片包含：

```
[状态徽标] [阶段] [画质标签] [条目进度 1/2] [文件数] [存在未完成条目] [重试次数]      时间
标题（解析到的标题，或链接）
████████░░░░░░░░░░░░░  67.3% · 3.2 MB/s · 剩 12s
已下载 24.4MB | 总大小 36.2MB | 速度 7.3MB/s | 剩余 12s | 耗时 1m31s
📁 …/downloads/xxx.mp4
[在访达中显示] [查看日志] [重试] [取消] [重试策略说明] [删除]
```

- **ASCII 块状进度条**：`████████░░` 比通用圆角进度条更直观
- **阶段文字**：解析链接 / 下载中 / 合流音视频 / 内嵌字幕 / 转码中 / 收尾
- **重试次数**：网络抖动与自动降级重试的累计次数（点击可看原因）
- **查看日志**：展开 yt-dlp 原始输出流，便于排障，可一键复制
- 顶部筛选：全部 / 进行中 / 已完成 / 失败·取消，另有「打开目录」「清理已结束」「重连进度」

## 2. 快捷键

| 按键 | 作用 |
|---|---|
| `/` | 聚焦 URL 输入框（不在输入框内时） |
| `Enter` | 单链接模式：开始解析；批量模式：投递全部 |
| `Shift+Enter` | 批量输入框内换行 |
| `Esc` | 清除当前解析结果 |

## 3. 高级参数详解

| 参数 | 说明 | 默认 |
|---|---|---|
| **音频格式** | 仅音频下载时的目标格式：mp3/m4a/opus/flac/wav | mp3 |
| **字幕语言** | 逗号分隔，如 `zh-Hans,zh-CN,en` | `zh-Hans,zh-CN,en` |
| **限速** | 如 `2M`、`500K`。网络不稳时配合并发分片=1 可显著降低断流 | 不限 |
| **并发分片** | 1–16。CDN 限速严格时调小（1–2）更稳 | 4 |
| **代理** | `127.0.0.1:7897` 或 `socks5://…`；不写协议自动补 `http://` | 无 |
| **Cookies 文件** | 导出的 cookies.txt 绝对路径 | 无 |
| **从浏览器读取 Cookies** | chrome/edge/firefox/brave/safari。macOS 上 Safari 可能受限 | 不用 |
| **播放列表条目** | 如 `1-5,8`；留空 = 全部 | 全部 |
| **自定义格式表达式** | 勾选后覆盖画质预设，直接传 yt-dlp `-f`，如 `bv*[height<=1080][vcodec^=avc1]+ba/b` | 不用 |

> 所有设置保存在浏览器 `localStorage`，下次打开自动恢复。

## 4. 典型场景

### 场景 A：下载 B 站 1080P 视频

1. 粘贴链接（如 `https://www.bilibili.com/video/BV1xx411c7mD`）
2. `Enter` 解析 → 选择「1080P」→ 点下载
3. 若是会员高码率内容，需先配置 Cookies（见场景 C）

### 场景 B：只要音频（做播客/音乐收藏）

1. 点「仅音频」预设（高级参数里可选 mp3/m4a/opus/flac/wav）
2. 下载完成后自动写入元数据并嵌入封面
3. 产物校验：`ffprobe` 显示 `audio:mp3` + 嵌入的 `video:mjpeg` 封面

### 场景 C：需要登录的站点（B 站高码率 / 部分 YouTube）

1. 打开「高级参数 → 从浏览器读取 Cookies」，选择你**已登录**的浏览器
2. 也可以导出 `cookies.txt` 后填写绝对路径
3. 重新解析即可

> 注意：带登录 Cookies 时 YouTube 有时会返回**更少**的画质
> （登录态走的播放器策略不同）。如果画质异常少，可以清空 Cookies 再试。

### 场景 D：批量下载

1. 切到「批量投递」模式
2. 每行一个链接（也支持空格/逗号分隔），一次最多 50 个
3. 点「投递 N 个」→ 自动排队，按并发数依次下载

### 场景 E：下载整个播放列表

1. 勾选「整个播放列表」后再解析 → 显示条目清单
2. 点「下载整个列表」；只想下前几集就填「播放列表条目」= `1-5`
3. 任务卡片会显示 `3/10` 条目进度；若有条目失败会标注「部分完成」

### 场景 F：网络不稳定，下载总断

1. 高级参数里把「并发分片」设为 `1`
2. 加「限速」如 `1M`（避免触发 CDN 限流）
3. 程序本身也会自动降级重试（4 级策略 + 退避等待）；取消后 `.part` 文件保留，重试可续传

## 5. 产物与目录

- 默认输出：项目内 `downloads/`（文件名 = 视频标题，截断 120 字节）
- 临时分片：`downloads/.part/`
- 任务卡片上的「在访达中显示」直接定位文件
- 队列顶部「打开目录」打开下载根目录

> 后端只允许操作 `downloads/` 内的路径（防目录穿越），无法用它打开任意系统路径。

---

## 6. 停止与重启

- `Ctrl+C` 停止服务：会先停 HTTP，再取消所有在跑任务（向进程组发 SIGTERM）
- 任务记录保存在内存，重启后队列清空，但**已下载的文件保留**
- 未完成的 `.part` 文件保留，重新下载同一视频会续传
